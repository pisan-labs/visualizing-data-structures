# Linear-bounded automaton

A linear-bounded automaton (LBA) is a Turing machine on a leash. Its input is written between two end markers, ⊢ and ⊣, and the head may read the markers but never move past them or overwrite them. So the machine has exactly the n cells it was given. No scratch space beyond that.

That sounds like a small change. It moves the machine down a whole level of the Chomsky hierarchy: LBAs accept exactly the **context-sensitive languages**, the ones generated by grammars whose rules never shrink.

| Operation | What it does | Cost |
|---|---|---|
| **Run** w | Writes ⊢w⊣ and runs the chosen machine, a step per move | Θ(n²) for aⁿbⁿcⁿ; space n + 2 cells, always |

## The bound

A Turing machine that runs out of input just keeps going into the blanks. An LBA can't. Its rules on ⊢ have to move right, its rules on ⊣ have to move left, and neither marker can be overwritten. The page enforces this: a rule that would step past a marker stops the machine on the spot.

[The bound stops a machine that needs more room](#example:the-bound) runs a machine that wants to write a copy of its input after the input. A Turing machine would happily do that. The LBA gets to ⊣ and is told no.

How much does that cost? Less than you'd think. An LBA may use more symbols than the input alphabet (x, y, z here), and by packing several symbols into one cell it can use k·n cells for any constant k. So "linear-bounded" really means *O(n) space*. What it can't do is use n² cells, or 2ⁿ.

```check
Q: Which of these can an LBA do on an input of length n?
- Write a copy of the input after it, using 2n cells
* Mark symbols in place, using a bigger tape alphabet
- Use as many cells as it likes, as long as it halts
= The head never passes ⊣, so there is no room after the input. Marking in place is how every machine on this page works.
```

## aⁿbⁿcⁿ

No PDA accepts aⁿbⁿcⁿ: a stack can match the a's against the b's, but then the count is gone before the c's arrive. An LBA has no such problem, because it can go back and look again.

The machine works in passes:
1. cross off the first a (write x), walk right to the first b and cross it off (y), walk right to the first c and cross it off (z);
2. walk back to the last x and start the next pass;
3. when no a is left, check that only y's and z's remain, then accept.

[aabbcc, one a, b and c per pass](#example:anbncn) [Show me](#play:anbncn)

A word with the right counts in the wrong order fails at step 3 ([Right counts, wrong order](#example:out-of-order)); a word one c short fails when a pass looks for a c and finds ⊣ ([One c short](#example:short-on-c)). Each pass walks across the tape, n/3 passes, so Θ(n²) moves.

The second machine in Options is Sipser's machine for a^(2^k), which halves the number of a's each pass. [Eight a's, halved three times](#example:power-of-two) accepts; [Six is not a power of two](#example:odd-count) halves to three and gets stuck on the odd one.

## Halting is decidable

Here is the nice part. An LBA on a word of length n can only be in so many configurations: a state, a head position, and the tape contents.

**|Q| · (n + 2) · |Γ|ⁿ**

That's a big number (the Variables panel shows it), but it's finite. A run longer than that must repeat a configuration, and a deterministic machine that repeats a configuration loops forever. So to decide whether an LBA accepts w, run it for that many moves: if it hasn't halted by then, it never will. Membership in a context-sensitive language is decidable.

Compare that with the [halting problem](/halting-problem/) for Turing machines. The only difference is the leash.

```check
Q: An LBA has 4 states and 3 tape symbols besides the markers. How many configurations does it have on a word of length 2?
- 24
* 144
- 4 · 3 · 2 = 24, times the 2 markers
= 4 states · 4 head positions (n + 2) · 3² tape contents = 144.
```

## Where it sits

| Level | Grammar rules | Machine |
|---|---|---|
| Regular | A → aB, A → a | DFA |
| Context-free | A → anything | PDA |
| **Context-sensitive** | **α → β with \|α\| ≤ \|β\|** | **LBA** |
| Recursively enumerable | anything | Turing machine |

Every context-free language is context-sensitive, and aⁿbⁿcⁿ shows the inclusion is strict. Above it, every context-sensitive language is decidable, but not every decidable language is context-sensitive. Have a look at the [Chomsky hierarchy](/chomsky-hierarchy/) page for the whole map.

Two famous loose ends. Is a nondeterministic LBA more powerful than a deterministic one? Nobody knows; it's the oldest open question in this area (the first LBA problem, from 1964). The second one, whether context-sensitive languages are closed under complement, was settled in 1988 by Immerman and Szelepcsényi, independently: yes.

## When to use it

Mostly to think with. Nobody parses with context-sensitive grammars in practice; they're too expensive, and membership is PSPACE-complete in general. The LBA is the cleanest way to say what "uses only linear space" means, and it explains why the context-sensitive level is decidable when the level above it isn't.

## Common mistakes

- **Thinking the bound means "n symbols of the input alphabet".** The tape alphabet can be bigger, which is how the machine marks things.
- **Forgetting the markers can be read.** The machine needs ⊣ to know where the input ends: q0 reading ⊣ is how aⁿbⁿcⁿ accepts.
- **Confusing "decidable" with "fast".** Counting configurations works, but the count is exponential in n.
- **Calling aⁿbⁿ context-sensitive and stopping there.** It is, but it is also context-free; aⁿbⁿcⁿ is the one that needs the LBA.
